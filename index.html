Flagship case study

Agents with guardrails, not just prompts.

Human-in-the-loop architecture: the agents do the legwork, and people hold every approval that matters.

Scoped access

Access limits live in each agent's tool definition. Seven of eleven agents can't reach an external system, whatever they're asked.

Read-only scoping

One agent turns a work item into a brief on a budget of roughly 10–12K tokens, and halts rather than inventing missing scope.

Draft pull requests only

Descriptions come from the real diff and commit log, not the brief. Auto-complete is forbidden by design.

Three-link completion

Nothing closes without a completed pull request, a passing test run and a documentation file that exists.

Human approval gates

Brief review, implementation, code review and merge. Merges, deploys and production migrations stay permanently human.

Coordination through files

Agents can't spawn or call each other. Everything passes through files on disk, so the audit trail stays readable.

How it runs

From vague idea to reviewed code.

01

Scope

A one-question-at-a-time interview turns an idea into a work item and child tasks. A read-only agent turns that into a brief.

02

Build

Backend and frontend agents implement the brief. A reviewer checks it. Documentation and tests follow. A human approves each gate.

03

Ship

A draft pull request is opened, a teammate reviews and merges, and the tracker closes only when it can prove the work is done.

illustrative
# illustrative sketch of the rule
close_work_item:
  requires:
    - pull_request: completed
    - test_run: passing
    - documentation: file_exists
  rejects:
    - handoff_notes   # WIP is not evidence
  order:
    1. transition_state
    2. post_comment
  can_reopen: false
  can_close_parent: false

Illustrative only. The real system is employer-internal.
